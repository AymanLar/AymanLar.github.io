## Context

Lyrics carry an emotional signal that is easy to feel and surprisingly hard to describe precisely. Is a song hopeful or melancholic? Does the chorus shift the mood of an otherwise dark verse? `sentrack` — a name combining *sentiment* and *track* — is a small web app built to answer those questions automatically.

Give it a song title and it fetches the lyrics from Genius, runs sentiment analysis with NLTK's VADER, and returns a visual report: colour-coded lyrics with hover annotations for each section, an overall positive/neutral/negative breakdown, and a chart. It also provides a YouTube search link so you can listen while you read along.

## Architecture

The application is a stateless Flask service with a single route. Everything needed to handle a request — the Genius client and the sentiment analyser — is created once at module load and shared across requests.

| Layer | Technology |
|---|---|
| Language | Python 3.11 |
| Backend | Flask |
| Lyrics source | Genius API via `lyricsgenius` |
| Sentiment engine | NLTK VADER (`SentimentIntensityAnalyzer`) |
| Configuration | `python-dotenv` |
| Frontend | HTML, Tailwind CSS (CDN), Chart.js (CDN), vanilla JS |
| Hosting | Vercel, with deployment workflows for Railway and Render |

The repository is compact:

```
app.py                       Flask app, Genius lookup, single / route
helpers.py                   lyrics cleaning, section parsing, VADER scoring
templates/index.html         entire UI plus inline client-side rendering logic
static/css/styles.css        tooltip styles
static/js/main.js            legacy code from an earlier audio-upload concept
vercel.json / Procfile       deployment configuration
.github/workflows/deploy.yml CI smoke test + three deployment jobs
```

There is no database, cache, or user account system. Results are computed on each request and returned as JSON; the browser does the rendering.

## How It Works

The full pipeline runs like this:

1. The browser submits the song title in a `POST` request to `/`.
2. `app.py` calls `genius.search_song(title)` and extracts the `lyrics` field. Any failure is caught and reported as "Song not found or lyrics unavailable".
3. `helpers.py` cleans the raw lyrics by removing the header Genius prepends before the first bracketed section marker.
4. The lyrics are split into sections using a regular expression with a capturing group: `re.split(r'(\[.*?\])', lyrics)`. This preserves markers such as `[Verse]`, `[Chorus]`, and `[Bridge]`, producing a list of `{type, text, lines}` dictionaries.
5. Each section is scored independently with `sia.polarity_scores()`, which returns a compound score plus positive, negative, and neutral proportions. Colours are assigned by threshold: `compound >= 0.1` is positive (green), `<= -0.1` is negative (red), and anything between is neutral (yellow).
6. The full lyric text is also scored as a whole to produce the overall mood and breakdown.
7. The server returns JSON containing the sections, the overall mood, the score, and a YouTube search URL. The client renders coloured lyric blocks with hover tooltips showing each section's exact sentiment percentages, followed by summary cards and a Chart.js bar chart.

The chart is destroyed before being redrawn, so repeated analyses do not stack canvases. The hover interaction comes from Tailwind's `group` / `group-hover` utilities backed by a small custom stylesheet.

A few implementation details are worth noting for anyone extending it: the overall mood uses a zero threshold while sections use ±0.1, so the same song can read as "Positive" overall while some sections are labelled neutral; the search is title-only, with no artist disambiguation; and the VADER lexicon is downloaded at import time, which adds a network dependency on the first run.

## Getting Started

Install the dependencies and provide a Genius API token:

```bash
pip install -r requirements.txt
```

Create a `.env` file in the project root:

```env
GENIUS_API_KEY=your_api_key_here
```

Then start the app:

```bash
python app.py
```

Open `http://127.0.0.1:5000`, type a song title, and click Analyse. The lyrics appear on the left with section-level colouring, while the mood summary and chart appear on the right. Hovering over a lyric section reveals its detailed sentiment breakdown; the YouTube link opens a search for the official music video.

For deployment, `vercel.json` routes all paths to `app.py` using the Python runtime, and `Procfile` plus `runtime.txt` cover Heroku/Railway-style platforms. The GitHub Actions workflow runs import smoke tests and then deploys to Vercel, Railway, and Render in parallel, using secrets configured in the repository settings. `DEPLOYMENT.md` documents the full setup, including how to obtain the Vercel credentials.

## Reflections

`sentrack` is an exploration of how far you can get with a small, focused stack: one API for content, one lexicon-based model for analysis, and a single page of JavaScript for presentation. The most interesting part of the implementation is the section-level parsing — treating a song as a sequence of labelled sections rather than one block of text makes the output far more meaningful than a single polarity score.

There is room to grow: escaping third-party lyric text before injecting it into the DOM, caching Genius responses, adding artist-aware search, reconciling the sentiment thresholds, and enabling more robust deployment settings are all on the list. For a weekend project, though, it delivers an immediate and genuinely fun way to look at the emotional shape of a song.
