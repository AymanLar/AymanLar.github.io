## Context

Compass is a mental-health awareness web app I built with a team during Chingu Voyage 35 — a seven-week remote collaboration with developers and designers from several time zones. The idea was straightforward: make a quick, private, non-judgemental way for people to reflect on two areas of their wellbeing — alcohol consumption and general psychological wellbeing — and get immediate feedback on whether their answers fall inside or outside of healthy ranges.

The app is built around two short questionnaires. After answering, users see an interpreted score and a short list of suggestions, such as considering a conversation with a therapist. There is no account, no server, and no data collection: everything happens in the browser, which matters for a topic where privacy is part of the user experience.

## Architecture

Compass is a static site. There is no build step, no package manifest, no framework, and no backend — just HTML, CSS, and vanilla JavaScript served directly by Netlify.

| Layer | Technology |
|---|---|
| Markup | HTML5 (7 pages) |
| Styling | Vanilla CSS3 with custom properties, flexbox, media queries |
| Logic | Vanilla JavaScript with `localStorage` |
| Icons | Font Awesome 5 CDN plus local SVGs |
| Fonts | Self-hosted Fira Sans and Poppins |
| Hosting | Netlify (static, no configuration file) |

The page structure mirrors the user journey:

```
index.html                       landing page with two assessment cards
pages/introduction.html          alcohol assessment intro and facts
pages/introduction(2).html       wellbeing assessment intro and facts
pages/alcohol_assessment/        10-question form + scoring + result page
pages/wellbeing_assessment/      18-question form + scoring + result page
css/                             global and per-section stylesheets
js/  scripts/                    menu, navigation, and scoring helpers
```

Styling is split into global tokens and per-page files. `css/style.css` defines the design system — a muted pink and plum palette (`--primary-color: #a56786`, `--accent-color: #ef5da8`), spacing variables, and a small set of utility classes such as `.row`, `.column`, and `.j-center`. That gave the team a shared vocabulary without pulling in a CSS framework. Responsive breakpoints cover everything from desktop down to 321 px screens.

## How It Works

The flow is entirely client-side:

1. The homepage links to an introduction page for each assessment, which presents a few context facts before the questionnaire.
2. Each assessment is a form with radio inputs named `q1`, `q2`, and so on. Because the questions are long, they are revealed one at a time using URL hash navigation (`#Question-2`, `#Question-3`, …) rather than separate pages.
3. On submit, a scoring script reads every checked input, accumulates per-choice counters, computes a total, stores it in `localStorage`, and redirects to the result page.
4. The result page reads the stored score, injects it into a circular progress indicator, and calls `scoreRating()` to write an interpretation and a list of suggestions.

The two assessments use different scoring models:

- **Alcohol consumption** follows an AUDIT-style approach. Answers to the first eight questions contribute through their most frequently selected frequency option, and the last two questions add a higher-risk weight. The result is interpreted in four bands: low risk (0–7), increasing risk (8–15), higher risk (16–19), and possible dependence (20+), each with tailored suggestions.
- **Psychological wellbeing** uses an 18-item scale with answers weighted from −3 to +3, giving a theoretical range of −54 to +54. Scores of 25 and above indicate strong wellbeing, scores between 0 and 25 suggest room for improvement, and scores at or below zero indicate that seeking support may be helpful.

Both patient-facing parts of the app treat the numbers as a starting point for reflection, not a diagnosis — the interpretation is deliberately framed around awareness and next steps.

Navigation is handled with small JavaScript helpers: a hamburger menu using CSS `clip-path` animations, smooth in-page scrolling on the homepage, and result-page actions for going home, starting over, or taking a different test.

## Getting Started

There is nothing to install. To run it locally:

```bash
git clone https://github.com/chingu-voyages/v35-toucans-team-03.git
cd v35-toucans-team-03
python -m http.server 8000
```

Then open `http://localhost:8000`. A local server is preferable to opening `index.html` directly because several asset paths are root-relative and only resolve correctly when the folder is served as the site root — which is why the Netlify deployment works without a `netlify.toml`.

No environment variables, build commands, or dependencies are required. The deployed version was available at `http://mental-compass.netlify.app/`.

The repository also reflects the team process: four GitHub issue templates (epic, user story, task, bug) and a contribution guide describing a fork → feature branch → pull request workflow into the `dev` branch.

## Reflections

Compass is a useful case study in building a functional product with no framework at all. The lack of a backend keeps privacy simple and hosting free, and the utility-class CSS system gave a distributed team enough structure to work in parallel.

It also carries the marks of a fast team project: duplicated stylesheets between the two result pages, unused scripts left over from an earlier circular-progress design, some stale asset paths, and scoring logic that would need careful clinical review before being treated as anything more than an awareness tool. Those are honest artefacts of a seven-week sprint with eight contributors and 237 commits.

The most valuable outcome for me was the collaboration itself — reviewing pull requests, resolving merge conflicts, and coordinating design and implementation across a remote team. The app is a small, working reminder of what a group can ship when the scope is clear and the stack stays simple.
